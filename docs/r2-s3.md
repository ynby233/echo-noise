# 云存储接入（R2/S3）

后台“存储配置”包含两套独立设置：附件存储与数据库云备份。开启附件云存储不会自动开启数据库备份，数据库备份也不等于已经复制了远端附件对象。本文主要说明数据库云备份；附件设置需单独保存。

## 配置字段

| 字段 | 填写方式 |
| --- | --- |
| 提供方 | R2（接口值 `r2`）或兼容 S3（`s3`）。 |
| Endpoint | 带协议的基础地址，不带 Bucket 或目录，例如 `https://<account-id>.r2.cloudflarestorage.com`、`https://s3.ap-northeast-1.amazonaws.com`。 |
| Region | R2 使用 `auto`；S3 使用厂商实际区域，例如 `ap-northeast-1`。 |
| Bucket | 单独填写桶名，例如 `note`。 |
| Access Key / Secret Key | 分别为访问密钥 ID 和机密访问密钥；保存后页面以“已配置”标志表示，留空保持原值，清除需显式操作。 |
| 路径风格 | R2 的后台选择逻辑设为开启，S3 按厂商要求设置 `usePathStyle`。直接调用配置 API 时也应正确保存此值；存储客户端按该字段决定路径风格。 |
| 公共访问前缀 | 可留空。数据库备份实现会把 URL 的路径部分当成对象 key 前缀，例如 `https://backup.example.com/note` 对应 `note/backup.zip`。修改它会改变后续上传、HEAD 和预签名所指的对象。 |

数据库备份不要求桶公开。预签名下载和自动同步使用认证访问，不依赖公共域名。备份含数据库及本地附件，通常应保持私有；公共前缀字段中的域名不是替代 S3 Endpoint 的签名地址。当前页面不提供旧文档所述“按公共前缀恢复”的独立操作，恢复应使用下载预签名 URL 或本地 ZIP。

密钥需要覆盖目标对象的上传、读取及 HEAD 元数据查询权限。自动同步会核对远端 ETag、Last-Modified 和大小，仅能 PUT 而不能读取元数据的权限不足以完成同步确认。

## 启用与同步行为

1. 在后台数据库云备份区域填写并保存配置，开启云存储。
2. 选择主节点（`primary`，执行同步）或备节点（`secondary`，不上传）；备节点不会自动变成拉取恢复节点。
3. 出现首次启用提示时，先确认目标桶和已有备份，再点击“确认同步”。后端同时检查数据库确认值和本机确认标记，复制数据库到另一实例不代表已在该实例确认。
4. 开启自动同步并保存：即时模式由业务调用 `syncmanager.Trigger()` 触发，使用 15 秒防抖；定时模式按正数分钟间隔运行。
5. 按需点击“立即同步”，检查返回结果与上次成功时间。

“立即同步”和自动同步共用 SQLite 仲裁流程，并非无条件上传：首次发现云端已有备份且本地从未记录同步元数据时优先下载；仅远端变化时下载并暂存恢复；仅本地变化时上传。两端都变化时以本地 mtime 和远端 Last-Modified 的两秒容差判断方向，无法可靠判断则报冲突并停止覆盖。应保持主机时钟准确，冲突时人工核对数据。

恢复暂存后返回 HTTP 202、`pendingRestart: true`，需要重启服务才应用；这不表示数据库已在线替换。恢复尚未应用时不继续覆盖云端。上传只有取得 2xx 并完成远端元数据核对才推进成功时间；失败保留旧成功时间。

## 备份包及迁移边界

SQLite 下载和云同步共用一致性归档实现，使用 `VACUUM INTO` 快照，ZIP 根目录包含 `database.db`，以及实际存在的以下目录：

- `attachment-blobs/`：当前本地 Blob 根（包括通过 `ATTACHMENT_BLOB_ROOT` 指定的外置根）。
- `images/`、`video/`、`audio/`、`attachments/`：兼容媒体及附件目录；图片源按配置解析。

这些是 ZIP 中的目录名，不是 `data/images/` 这样的完整运行路径。旧 ZIP 没有新附件目录时可恢复正文，但会返回不完整迁移警告，不能把它称作完整备份。普通网页 ZIP 不包含整套运行环境或远端对象存储桶，迁移时需另外保存配置、密钥和远端对象。

MySQL/PostgreSQL 的手动下载/上传路径还会调用 `mysqldump`/`pg_dump` 生成数据库导出，并归档兼容图片、视频；需要服务运行环境具备对应客户端工具。自动同步的非 SQLite 分支 `syncUploadLegacy` 只打包本地 `data/images` 和 `data/video`，不导出数据库，也不包含完整 Blob 根或双向仲裁，不能作为数据库备份。不要将不同数据库类型的 ZIP 或外部数据库恢复当成 SQLite 重启暂存流程。

## 预签名与 API

预签名 URL 默认有效期 3600 秒，是有效期内可使用的授权链接，**不是一次性 URL**；不要公开 URL 或将其写入共享日志。上传签名建议保持 `Content-Type: application/zip`，服务端上传也使用此类型。

后台对应的实际接口如下，全部要求登录及对应能力，成功业务响应使用 `code: 1`。表中能力还受授权目录的父能力约束。

| 方法与路径 | 请求与结果 | 能力 |
| --- | --- | --- |
| `GET /api/backup/download` | 下载本地 ZIP。 | `database.backup` |
| `POST /api/backup/restore` | multipart 字段 `database` 上传 ZIP，当前限制 500 MiB；SQLite 成功暂存返回 202。 | `database.restore` |
| `POST /api/backup/storage/presign/upload` | JSON `{}` 或 `{"expiresSeconds":3600,"contentType":"application/zip"}`；返回 `data.url/objectKey`。 | `database.backup` |
| `POST /api/backup/storage/presign/download` | JSON `{}` 或 `{"expiresSeconds":3600}`；返回 `data.url/objectKey`。 | `database.restore` |
| `POST /api/backup/storage/upload` | `{"uploadURL":"<预签名 PUT URL>"}`，由服务端生成并上传 ZIP。 | `database.backup` |
| `POST /api/backup/storage/restore` | `{"downloadURL":"<预签名 GET URL>"}`，由服务端下载并校验；SQLite 返回 202 和 `pendingRestart: true`。 | `database.restore` |
| `POST /api/backup/storage/sync-confirm` | 确认当前实例云同步。 | `storage.manage` |
| `POST /api/backup/storage/sync-now` | 执行同步仲裁；可能上传、无变化或暂存恢复。 | `storage.manage` |

预签名接口固定基础对象名为 `backup.zip`，即使传入 `objectKey` 也会被覆盖；最终 key 再叠加公共访问前缀的路径。它不是按时间保留多个版本的备份系统，需要历史版本时使用桶版本控制或另行归档。

页面当前提供预签名生成按钮，生成后可用于上述上传/恢复接口。不要把“生成链接成功”当作“备份已上传”或“恢复已完成”。SQLite 恢复会先验证并暂存，启动时在打开数据库前应用；旧数据回退及实际重启行为见 [维护指南](maintenance.md)。

## 常见问题

- 403 或签名不匹配：核对 Endpoint、Bucket、Region、路径风格、对象前缀和密钥权限；重新生成链接并核对有效期、主机时钟和上传 Content-Type。
- 同步未启动：核对云存储开关、自动同步开关、主节点角色、首次确认，以及定时模式的正数间隔。备节点的手动同步请求会被拒绝。
- 上传成功但同步时间未更新：查看 HEAD 元数据核对是否失败，不要只根据对象存在判断整个同步成功。
- 恢复提示需重启：这是 SQLite 暂存成功的正常结果；先保存当前工作，按部署方式重启并核对 readiness、正文和附件。
